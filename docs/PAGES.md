### 访问控制

| 级别 | 页面 | 理由 |
|---|---|---|
| **公开** | 竞赛列表/详情、日历、队伍列表/详情、用户名片 | 分享给人看不用先注册；**且利于搜索引擎收录，是冷启动的重要流量来源** |

> **注意**：公开页里出现的用户信息一律走**半匿名规则**（专业/年级/技能可见，学号姓名不可见），见 §5。

## 2. 竞赛雷达

### 2.1 首页 `/`　P1

登录与否都能看。第一屏要回答"**现在有什么比赛我能参加**"。

| 区块 | 内容 | 数据来源 |
|---|---|---|
| 搜索框 | 置顶，竞赛名/别名模糊搜索 | `Competition.name` + `aliases` |
| **「只看能加分的比赛」入口** | 显眼位置，一键筛选 | `Competition.isBonusEligible` |
| **近期 DDL 倒计时** | 未来 30 天内报名截止的竞赛，按剩余天数升序 | `CompetitionTimeline` |
| 热招队伍 | 状态为「招募中」的队伍卡片 | `Team` |
| 日历预览 | 本月迷你日历 | `CompetitionTimeline` |
| 按级别入口 | 国际级 / 国家级 / 省级 / 校级 四色入口 | `CompetitionLevel` |
| **适合你的竞赛**（需登录） | 按学院 / 专业 / 年级 / 学科标签匹配的推荐位 | `Competition` **规则筛选** |
| 热门经验帖 | 经验库精华帖子 | `Post` |

> 「只看能加分的比赛」是**核心刚需入口**，必须在首屏可见 —— 这是本站相对论坛最不可替代的价值。

> **注意区分**：「适合你的竞赛」是**规则筛选**（按字段匹配），不是算法推荐。本站不做智能匹配算法，理由见 [MODULE_MATCH.md](./MODULE_MATCH.md) §1。

### 2.2 竞赛列表 `/competitions`　P1

**筛选维度**（左侧栏 / 移动端抽屉）：
- 级别（四档，多选）
- 学科标签
- 面向年级（本科生 / 研究生 / 混合）
- 赛制（个人 / 团队）
- **是否能加分**
- 状态（报名中 / 即将开始 / 已结束）

**排序**：报名截止临近 ｜ 最新收录 ｜ 难度 ｜ 热度

**列表项要素**：竞赛名 + 级别色标 + 学科标签 + 报名截止倒计时 + "N 支队伍正在招募"

**视图切换**：卡片视图 ｜ 表格视图（Element Plus `el-table`，适合密集浏览）

### 2.3 竞赛详情 `/competitions/:id`　P1

这是全站信息密度最高的页面，也是**两个模块的交汇点**。

| 区块 | 内容 |
|---|---|
| 头部 | 名称 / 别名、级别色标（可能多个）、状态、**最后更新时间** |
| 关键信息卡 | 主办方、官网、赛制（个人/团队+人数）、面向年级、难度、投入度 |
| **推免加分卡** | 是否计入、认定类别、分值。**为空时显示"暂无认定信息"，不要显示空白** |
| 时间轴 | 各阶段起止时间 + **每个节点自己的级别**；临近的节点高亮 |
| 竞赛简介 | 管理员填写 |
| **正在招募的队伍** | ⭐ 本竞赛下状态为「招募中」的队伍卡片 + "我也要组队"按钮 |
| 往届真题 / 开源作品 | `CompetitionMaterial` |
| 本校历年获奖 | `CompetitionAward` |
| 经验帖 + 留言讨论 | `Post` 聚合 + `Comment` |
| **来源与纠错** | "信息来源：XX 官网 ↗（最后更新 3 天前）" + **每个字段旁的「报告错误」入口** |
| 操作栏 | 关注 / 收藏 ｜ 导出 .ics ｜ 分享海报（P3） |

> 「报告错误」入口是全自动发布模式的**事后纠错执行入口**，必须做，且位置要显眼但不干扰阅读。

### 2.4 竞赛日历 `/calendar`　P1

用 **FullCalendar**，不要手写。

| 功能 | 说明 |
|---|---|
| 月视图 | 每个竞赛一条彩色跨天条带，**「报名期」与「赛程期」用两类样式区分** |
| 按级别配色 | 国际/国家/省/校 四色 |
| 点击日期 | 侧栏列出当天所有节点（竞赛名、阶段、级别） |
| 点击节点 | 跳竞赛详情页 |
| 筛选 | 按级别、学科、是否已关注叠加 |
| 列表视图 | 按 DDL 倒序，"距报名截止还有 N 天" |
| **导出 .ics** | 订阅到手机日历。**学生 90% 在手机上，这比站内提醒有用 10 倍** |

> ⚠️ 原稿筛选维度里还有「校区」，但竞赛档案没有校区字段，见 [OPEN_QUESTIONS Q4](./OPEN_QUESTIONS.md)。

### 2.5 经验库 `/library`　P2

真题、开源仓库、经验帖、答辩模板的汇集地。**这是"避坑指南"，也是本站沉淀知识资产的地方** —— 论坛里的经验帖会沉底，这里不会。

| 功能 | 说明 |
|---|---|
| 分类浏览 | 按竞赛、按类型（真题 / 开源作品 / 经验帖 / 答辩模板） |
| 发布 | 用户可发帖，`Post.kind` 区分类型 |
| 互动 | 点赞、收藏、**加精**（管理员/贡献者操作） |
| 关联 | 经验帖自动聚合到对应竞赛详情页 |

## 3. 队友匹配

### 3.1 队伍列表 `/teams`　P1

**列表项要素**：竞赛名 + 队伍状态徽章 + 目标 + **缺口角色标签** + 队长 + 已有成员数 + 招募截止倒计时

**筛选维度**：
- 竞赛
- **缺口角色**（算法/前端/后端/硬件/建模/UI/论文/答辩/其他）
- 目标（保奖/学习练手/冲国一/只为加分）
- 状态（招募中/暂停招募/已满员/已参赛）—— `已解散` / `已归档` 不进入公共发现列表
- 年级

> ⚠️ 原稿筛选维度含「技能标签、校区、投入时长」，但 v0.3 组队卡已删除这三个字段。筛选维度必须与卡片字段对齐，见 [OPEN_QUESTIONS Q1](./OPEN_QUESTIONS.md)。

**默认排序**：招募截止临近 ｜ 最新发布
**默认过滤**：**默认只显示 `RECRUITING`**；PAUSED / FULL / COMPETING 需手动开启；
`DISBANDED`（队长解散）与 `ARCHIVED`（系统归档）永不出现在公共发现列表，避免僵尸帖。

### 3.2 队伍详情 `/teams/:id`　P1

| 区块 | 内容 |
|---|---|
| 头部 | 竞赛名（可跳转）、状态徽章、目标、招募截止倒计时 |
| 缺位情况 | 各缺口角色 + 是否已招到 |
| **已有成员情况** | rank / 年级 / 学院 / 备注 |
| 招募要求 | 队长填写的自由文本 |
| 联系方式 | ⚠️ 按隐私规则决定是否公开展示，见 §5 与 [Q8](./OPEN_QUESTIONS.md) |
| 操作 | **申请加入**（填自我介绍+技能证明）／ 队长视角：审批申请、发邀请、改状态、关闭招募 |
| 关联竞赛卡 | 反向挂载竞赛档案摘要 —— **两个模块双向联动的另一半** |

### 3.3 发布组队 `/teams/new`　P1

表单字段严格对齐 [DATA_MODEL.md](./DATA_MODEL.md) §6 的 `Team` + `TeamMember` + `TeamSlot`：

1. 选择竞赛（搜索选择器，找不到可申请新增）
2. 目标（单选）
3. **缺口名额**（每行 = 一个方向 + 数量，如「算法 ×2 / 论文 ×1」；同一方向可有多个名额）
4. 已有成员情况（**仅平台外成员**；平台注册同学须走申请/邀请，不得直接填 userId）
5. 招募要求（文本域）
6. 招募截止时间（日期选择，**默认填竞赛报名截止时间**）
7. 联系方式

> **降低发帖门槛**：除"选择竞赛 + 目标 + 缺口方向"外，其余字段允许留空。字段全必填会直接劝退一半用户。
>
> **人数不再手填**：当前成员数 = 活跃 `TeamMember` 数，剩余 = `OPEN` 名额数，目标 = 两者之和，由服务端实时推导。

### 3.4 求带广场 `/wanted`　P2

"我想打 XX 比赛，求带"的个人帖 —— 与队伍招募互为镜像。字段更轻：竞赛、我能做什么、我能投入多少、联系方式。

### 3.5 队伍空间 `/teams/:id/workspace`　P2

组队确认后自动生成。**这是"把沟通沉淀在站内"的载体**，也是本站相对微信群的核心优势。

| 模块 | 说明 |
|---|---|
| 讨论区 | 帖子式，支持 @ 提及 |
| 文件共享 | PPT / 代码 / 论文，注意磁盘容量 |
| 任务看板 | 待办 / 进行中 / 已完成 |
| 里程碑 | 复用竞赛时间轴 + 自定义节点，带提醒 |
| 投票 | 决策用（约时间、定方案） |

> **MVP 不做**。P1 阶段组队成功后引导用户加微信即可 —— 先验证"能不能匹配上"，再解决"匹配上之后怎么协作"。

## 5. 半匿名规则（全局约束）

| 状态 | 可见信息 |
|---|---|
| 陌生人 | 昵称、学院、年级、专业、技能标签、参赛经历 |
| **确认组队后** | 学号、姓名、联系方式 |
| 管理员 | 全部 |

**理由**：降低发帖心理门槛。同学不愿在公开网络留下"我是 2024 级 XX 学院 XXX"，但愿意留下"2024 级计算机，会写后端"。

**实现**：后端在序列化用户对象时按关系动态裁剪字段，**不能只靠前端隐藏**。

## 6. 管理后台 `/admin/*`　P1（最小集）/ P2（完整）

| 页面 | 功能 | 阶段 |
|---|---|---|
| `/admin/sources` | 数据源 CRUD、选择器在线编辑、启用停用、健康状态 | P1 |
| `/admin/competitions` | 竞赛录入 / 编辑 / 下线（含推免加分字段） | P1 |

| **`/admin/revisions`** | **版本历史与一键回滚** —— 全自动模式的恢复通道 | P2 |

## 7. 关键用户流程

### 7.1 核心闭环：从发现竞赛到组队成功

```
首页「近期 DDL」/ 日历
        ↓ 点进
   竞赛详情页
        ↓ 看到「本竞赛下有 3 支队伍正在招募」
        ↓ 或点「我也要组队」
   队伍列表（已按本竞赛过滤）
        ↓
   队伍详情 ── 不合适 → 返回列表
        ↓ 合适
   点「申请加入」+ 写自我介绍
        ↓
   队长收到通知 → 审批
        ↓ 通过
   双方解锁完整信息 → 加微信 / 或用队伍空间
```

**这条链路上任何一环断掉，产品就废了。** 尤其注意：竞赛详情页 → 队伍列表的跳转必须带上竞赛过滤，否则用户要在队伍列表里重新找一遍这个竞赛。

### 7.2 纠错流程

```
用户在竞赛详情页发现截止时间不对
        ↓ 点字段旁「报告错误」
   填写"我认为应该是 XX"
        ↓
   CorrectionReport 入库，PENDING
        ↓ 进入 /admin/corrections（优先级高于采集任务）
   管理员核对来源 → 采纳 / 驳回
        ↓ 采纳
   写入 CompetitionTimeline，同时：
   ├─ 记入 CrawlRevision（origin = MANUAL）
   └─ isLocked = true  ← 防止下次采集改回去
```

## 8. 横向功能

不属于某个单独页面、但贯穿全站的能力。

| 类别 | 功能 | 阶段 |
|---|---|---|
| 通知 | 站内信 + 邮件；**采集异常告警、源失效告警、DDL 提醒、申请通知**四类 | P1 |
| 检索 | 竞赛 / 经验帖 / 用户 统一搜索 | P1 |
| 激励 | **贡献值** —— 补全竞赛信息、提交纠错被采纳、帮助队友 | P2 |
| 增长 | **一键生成分享海报**（转发 QQ 群 / 朋友圈），冷启动利器 | P3 |
| 移动 | 自适应 + PWA（可添加到桌面） | P1 自适应 / P2 PWA |
| 后台 | 见 §6 | P1 / P2 |
| 开放 | 公开 API，供校园论坛 / 学生会小程序调用竞赛数据 | P3 |
