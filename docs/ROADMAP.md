# 路线图与任务拆解

> 相关：[README.md](./README.md)（项目速览）、[PAGES.md](./PAGES.md)、[OPEN_QUESTIONS.md](./OPEN_QUESTIONS.md)

每个任务都写了**验收标准** —— 一条能跑通、能看见、能给别人演示的标准。
"写完了"不是标准，"能演示"才是。

## P0 ｜ 排雷周（1 周）

**这一周不写业务代码，只排除会让后面全部白干的阻塞项。**

| # | 任务 | 验收标准 |
|---|---|---|
| 0.1 | ⭐ **QQ 邮箱送达率实测** | 向 5–10 位不同学院同学真实发验证码，逐一确认收到/进垃圾箱/延迟。**结果写进文档** |
| 0.2 | 确认学号规则 | 见 [OPEN_QUESTIONS Q10/Q11](./OPEN_QUESTIONS.md)；**解析失败不阻塞注册** |
| 0.3 | 启动 ICP 备案（若用国内服务器+域名） | 备案流程已提交 |
| 0.4 | pnpm workspace 脚手架 | `apps/api` + `apps/web` + `packages/shared` 三个包能互相引用，`pnpm dev` 同时起前后端 |
| 0.5 | Docker Compose 本地环境 | `docker compose up` 起来 PG 16 + Redis 7，`psql` 能连上 |
| 0.6 | Prisma 接入 + 首个迁移 | `users` 表建出来，`prisma migrate dev` 通过 |
| 0.7 | 登录流程打通 | 手机/电脑打开页面 → 输学号邮箱 → 收到验证码 → 登录成功 → 数据库里有这条 user |
| 0.8 | 部署流水线 | GitHub Actions push → 构建镜像 → SSH 部署到服务器 → 浏览器能打开一个页面 |

**P0 出口条件**：**能在手机上用自己的学号登录一个部署在公网的页面。** 达到这个状态，项目就"活了"。

> ⚠️ 如果 0.1 实测不通过，立刻切 [MODULE_AUTH.md](./MODULE_AUTH.md) §8 的兜底方案，**不要先写登录再补**。

## P1 ｜ MVP（3 周）

**目标：能演示完整的"发现竞赛 → 找到队伍 → 申请加入"闭环。**

### 竞赛雷达

| # | 任务 | 验收标准 |
|---|---|---|
| 1.1 | 竞赛档案 CRUD + 管理后台录入页 | 能手工录入一个竞赛，含级别（可多选）、推免加分、时间轴 |
| 1.2 | ⭐ 异常拦截器 | 构造一条日期为 1970 的假数据，**能被拦住并产生告警**，不写进库 |
| 1.3 | 竞赛列表页 + 筛选 | 按级别/学科/年级/赛制/是否加分筛选生效 |
| 1.4 | 竞赛详情页 | 所有区块齐全；「正在招募的队伍」区块能显示对应队伍 |
| 1.5 | ⭐ 竞赛日历（FullCalendar） | 月视图显示跨天条带，按级别配色；点击日期出侧栏；**导出 .ics 能被手机日历正确导入** |
| 1.6 | 采集跑通 1–2 个源 | 定时任务能自动抓到一个真实竞赛并发布；**同一个源跑两次不会产生重复竞赛** |
| 1.7 | 版本快照 | 每次自动更新都能在库里查到旧值 |
| 1.8 | 搜索 | 输入竞赛名/别名能搜到 |

### 队友匹配

| # | 任务 | 验收标准 |
|---|---|---|
| 1.9 | 发布组队 | 表单能创建队伍，缺口角色多选生效 |
| 1.10 | 队伍列表 + 筛选 | 按竞赛/缺口角色/目标/状态筛选生效；**默认不显示已满员队伍** |
| 1.11 | 队伍详情页 | 显示已有成员情况、招募要求、关联竞赛卡 |
| 1.12 | ⭐ 申请-审批双向流 | A 申请 → B 收到站内信 → B 同意 → A 成为队员 + 双方解锁完整联系方式 |
| 1.13 | 状态机 + 自动过期 | 把 `deadline` 改成昨天，跑一次 cron，**该队伍应从招募列表消失或标记已截止** |
| 1.14 | 半匿名 | 用 A 账号看不认识的 B 的名片 → **看不到学号**；组队后 → 能看到 |

### 基础设施

| # | 任务 | 验收标准 |
|---|---|---|
| 1.15 | 站内通知 | 申请、审批、DDL 提醒四类通知能正常产生与展示 |
| 1.16 | DDL 提醒 | 关注竞赛后，截止前 7/3/1 天能收到邮件+站内信 |
| 1.17 | 个人中心全部子页 | 资料编辑、我的队伍、我的申请、我的关注、消息中心可用 |
| 1.18 | 移动端适配 | **在手机上完整走通核心闭环**（这一步不要留到最后做） |

**P1 出口条件**：**找一个真实同学，不看说明，让他在手机上完成"注册 → 找一个比赛 → 申请加入一支队伍"。全程无卡点。**

### P1 的两条纪律

1. **采集只跑通 1–2 个源**，不要一上来接 20 个站点
2. ⭐ **异常拦截器（1.2）必须在接第 3 个源之前完成** —— 先有刹车，再踩油门

## P2 ｜ 安全带与后台（2–3 周）

**目标：让全自动发布真正安全，让运营可持续。**

| # | 任务 | 验收标准 |
|---|---|---|
| 2.1 | 版本回滚页 | 管理员能一键把一个字段回滚到上一版本，且**回滚动作本身也被记为一条 revision** |
| 2.2 | 用户纠错入口与处理台 | 竞赛详情页能提交纠错 → `/admin/corrections` 能看到 → 采纳后**节点自动加锁** |
| 2.3 | 单源熔断 | 构造一个源产生 21 条更新，**该源应被自动暂停**并告警 |
| 2.4 | 源失效告警 | 故意改坏一个选择器 → 连续跑 N 天 → **收到告警** |
| 2.5 | 数据源管理后台 | 能在线改选择器配置，**不用发版** |
| 2.6 | 用户纠错奖励 | 纠错被采纳 → 贡献值 +1 |
| 2.7 | 多源扩展 | 接入 5+ 个源，稳定运行 1 周无异常 |
| 2.8 | 队伍空间 | 讨论区、文件、任务看板、里程碑 |
| 2.9 | 经验库 | 能按竞赛/类型浏览、发帖、点赞收藏、管理员加精 |
| 2.10 | 求带广场 | 个人发布"求带"帖 |
| 2.11 | 举报处理 | 能举报队伍/用户/评论，管理员能处理 |
| 2.12 | PWA | 手机浏览器能"添加到桌面"，有图标 |
| 2.13 | 移动端底部 Tab | 竞赛 ｜ 日历 ｜ 组队 ｜ 我的 |

**P2 出口条件**：**连续 1 周不用人工干预，采集数据无异常；出现错误能在 1 小时内发现并回滚。**
