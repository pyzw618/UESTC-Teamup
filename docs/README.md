## 一页速览

**要解决的问题**
1. 竞赛信息支离破碎，靠 QQ 群口口相传，容易错过 DDL
2. 论坛找队友低效、帖子易沉底、状态不更新，占满论坛版面

**两大核心模块**

| 模块 | 定位 | 核心机制 |
|---|---|---|
| **竞赛雷达** | 自动监听竞赛信息源，别错过任何 DDL | 定时采集 → 自动发布 → 事后纠错 |
| **队友匹配** | 集结成队，把沟通沉淀在站内 | 结构化组队卡 + 状态机 + 申请审批流 |

**命名决策**：采用直白命名而非隐喻（备选的「灯塔 Beacon / 舰队 Fleet」已否决），理由是零认知成本、SEO 关键词天然友好。

**两个模块必须双向联动** —— 竞赛详情页挂载"本竞赛下有 N 支队伍正在招募"，组队卡反向挂载竞赛档案。
**不联动，这个产品就失去存在意义。**

### 核心产品洞察：推免加分

成电同学打竞赛的核心驱动力之一是**推免加分**。级别与推免加分是**两套口径**，不可互相替代：

| 字段 | 回答的问题 | 数据来源 |
|---|---|---|
| 级别（四档：国际 / 国家 / 省 / 校） | 这比赛**多大** | 爬虫 + 人工判断 |
| 推免加分 | 这比赛**对我保研有没有用** | 校教〔2026〕39 号文 |

支持「只看能加分的比赛」筛选 —— **首页必须有显眼入口**，这是本站相对论坛最不可替代的价值。

**三个"不做"决定（和"做"同样重要）**
- ❌ **不做微服务** —— 2C2G 单机，单体 + 模块化边界
- ❌ **不用无头浏览器** —— 内存扛不住，只抓静态可解析的源
- ❌ **不做智能匹配算法** —— 冷启动期数据密度不够，做了也空转（P3 再评估）

**三条硬约束**
- 服务器 2 核 2G，峰值用户 < 1000（真实并发仅几十）
- 邮件走个人 QQ 邮箱 SMTP，**有每日发信限额，送达率必须实测**
- 国内服务器 + 域名需 ICP 备案，流程 2–4 周

**开工第一件事**：向 5–10 位不同学院同学真实发送验证码，确认是否收到/进垃圾箱。**这个结果决定登录方案是否成立。**
