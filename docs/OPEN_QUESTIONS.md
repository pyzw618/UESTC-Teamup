## A 类：设计稿内部前后矛盾（改动后遗留）

这些是 v0.3 修改后产生的不一致，**会让开发者不知道听谁的**，必须先定。

### Q1 ⭐ 组队卡的筛选维度与字段对不上

- **矛盾**：早期设计稿的「队友匹配」小节说筛选维度含「技能标签、校区、投入时长」
- **但**：v0.3 改版后的组队卡字段里已经**删掉了这三项**（改成「招募要求」自由文本 + 「已有成员情况」）
- **影响**：前端筛选器无从下手；后端 `Team` 表没有对应字段可查
- **建议**：筛选维度改为 **竞赛 / 缺口角色 / 目标 / 队伍状态 / 年级** —— 这五个都有结构化字段支撑。若确认要按技能筛，需把技能标签加回组队卡

### Q2 信誉分删了，但互评体系还在

- **矛盾**：`users` 表删除了「信誉分」字段，但 §2.2 功能 6 的「双向匿名互评」仍然保留，`Review` 表也在
- **影响**：互评结果**存在但没有展示位置** —— 用户看不到任何评分汇总，互评就等于白做
- **建议**：二选一 ——（a）互评结果只作为文字评论展示，不做分数聚合；（b）加回信誉分字段，由 `Review` 聚合计算

### Q3 头像字段被删

- **矛盾**：`users` 表删除了「头像」
- **影响**：队伍卡片、申请列表、成员列表没有头像会显得很干；但头像需要文件上传 + 存储 + CDN，确实是额外工作量
- **建议**：确认是「确认不要」（用昵称首字母色块兜底）还是「遗漏」

### Q4 日历按「校区」筛选，但没有校区字段

- **矛盾**：§2.1.4 日历筛选维度含「校区」，但竞赛档案里没有校区字段；组队卡的「期望校区」也已被删除
- **影响**：这个筛选项没有数据来源
- **建议**：二选一 ——（a）删除该筛选项；（b）在竞赛档案加「举办校区」字段

### Q5 仓库结构里 admin 注释过时

- **矛盾**：[TECH_STACK.md](./TECH_STACK.md) 早期版本里 `admin/` 注释写「含采集审核队列」，与 v0.3「全自动发布」矛盾
- **状态**：✅ **已在拆分时修正**为「数据源管理 / 异常拦截 / 版本回滚 / 纠错处理 / 举报」，此处仅备案

### Q6 `user_skills` 表保留，但失去了使用场景

- **矛盾**：`UserSkill` 表还在，但组队卡已不再要求技能标签
- **影响**：技能标签的唯一用途只剩「个人能力名片」（PAGES.md §4.2）
- **建议**：二选一 ——（a）保留，明确它服务于个人名片 + 为 P3 智能匹配预留数据；（b）砍掉，等 P3 再加
- **注意**：现在砍掉，P3 做匹配时就没有历史数据积累

### Q7 竞赛详情页新增「留言讨论」

- **矛盾**：v0.3 在竞赛档案加了「留言讨论」，但原 `Comment` 表只服务于帖子

## B 类：需要用户拍板的设计问题

### Q8 ⭐ 组队卡上的「个人联系方式」怎么展示？

- **现状**：v0.3 组队卡字段含「个人联系方式」，是自由文本
- **风险**：**如果公开展示，等于把一份可被爬取的成电学生联系方式清单挂在公网上。** 爬虫、推销、诈骗都会盯上
- **选项**：
  - (a) 登录可见，不登录看不到 —— 挡掉大部分爬虫，但仍可被注册用户批量爬取
  - (b) 不公开展示，**申请通过后才站内可见** —— 最安全，但增加了沟通成本
  - (c) 展示时加图形验证/水印 —— 麻烦且挡不住
- **建议 (b)**：这也正好符合"把沟通沉淀在站内"的产品目标
- **需要决策**

### Q9 `isLocked` 人工锁定机制（拆分时新增）

- **背景**：管理员手工修正过的时间节点，下次采集会**被改回去**，而且看起来像"数据自己变回去了"这种灵异现象
- **方案**：`CompetitionTimeline.isLocked` —— 人工编辑过的节点加锁，爬虫遇到加锁节点只告警不写入
- **状态**：已写入 [DATA_MODEL.md](./DATA_MODEL.md) §4.2 和 [MODULE_CRAWLER.md](./MODULE_CRAWLER.md) §6
- **需确认**：是否采纳。**没有它，人工修正形同虚设。**

### Q10 学号解析规则

- **待确认**：`2024080909015` 中间位的学院编码规则
- **影响**：注册时自动填充学院/年级
- **注意**：解析失败**不能阻塞注册**，允许为空后续补全

### Q11 学号位数是否统一？

- **现状**：[MODULE_AUTH.md](./MODULE_AUTH.md) 的正则按 13 位写（`\d{13}@std\.uestc\.edu\.cn`）
- **风险**：**研究生、留学生、非全日制**的学号可能是别的位数或格式；而竞赛档案的「面向年级」明确包含研究生
- **建议**：放宽为 `^\d{8,16}@std\.uestc\.edu\.cn$`，格式细节交给后续校验
